# Отправка демки на GitHub

Применяй этот навык, когда пользователь явно просит отправить текущие изменения на GitHub. Обычные задачи по редактированию демки не разрешают отправку. Push в main запускает обновление публичного GitHub Pages.

## Репозиторий

Используй существующий checkout `pershmary/table-widget`, обычно `/workspace/table-widget`. Не создавай worktree. Проверь текущие инструкции репозитория и `rules.md`. Не публикуй облачную среду: это отдельная операция.

## Подготовка

1. Проверь `git status --short`, текущую ветку, последний коммит и origin. Не удаляй и не перезаписывай посторонние изменения.
2. Посмотри diff и новые файлы. Не добавляй секреты, загруженные архивы, временные проверки или скриншоты. Уточняй только действительно неоднозначный состав отправки.
3. Пересобери автономный просмотр из корня checkout: `python3 tools/build-demo.py`. В `index.html` должны попасть изменения `demo.html`, CSS, JS, SVG и локальных шрифтов.
4. Выполни `git diff --check` и `node --check` для изменённых JS. Изменения поведения проверяй в браузере; для небольшой текстовой правки или ссылки достаточно проверить соответствующие DOM-элементы и значения. Не считай отсутствие ошибок синтаксиса проверкой интерактивности.
5. Проверь `git ls-remote origin refs/heads/main`. Если main продвинулся, получи изменения через штатный HTTPS Git proxy, изучи их и аккуратно интегрируй, сохраняя локальную работу; повтори затронутые проверки. Не используй force push или reset для обхода конфликта.

## Отправка

1. Добавь только относящиеся к задаче файлы явным списком; просмотри `git diff --cached --stat` и `git diff --cached --check`.
2. Создай коммит с кратким описанием фактических изменений. Если изменений нет, проверь, есть ли уже созданные, но не отправленные коммиты.
3. При неизменном назначении origin отправь `git push origin HEAD:main`. Явная команда пользователя уже разрешает этот шаг; повторное подтверждение не требуется.
4. Проверь завершение push и совпадение `git rev-parse HEAD` с `git ls-remote origin refs/heads/main`. Проверь итоговый статус рабочей папки.
5. Сообщи коммит и ссылку `https://pershmary.github.io/table-widget/`. Отправка не доказывает успешное развёртывание Pages: утверждай, что сайт обновлён, только после проверки деплоя. Иначе сообщи, что обновление сайта ожидается после развёртывания.

Не запрашивай GitHub-токен только из-за отсутствия переменной окружения: сначала используй существующую аутентификацию платформы. При отказе в push сохрани коммит и сообщи точный блокер, не извлекая и не печатая учётные данные.
